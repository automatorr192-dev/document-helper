# Документ-хелпер

[![CI](https://github.com/automatorr192-dev/document-helper/actions/workflows/ci.yml/badge.svg)](https://github.com/automatorr192-dev/document-helper/actions/workflows/ci.yml)

Показывает, какие пункты договора могут стоить тебе денег. Бросаешь PDF — получаешь разбор:
что опасно, что спорно, что нормально, и что исправить до подписи.

**Живое демо → скоро**

## Зачем

Договор подписывают все, а читают его до конца единицы. Плохой пункт замечают, когда деньги
уже сгорели: невозвратная предоплата, автопродление, штраф без потолка, право второй стороны
менять условия задним числом. Юрист за вычитку берёт от 3 000 ₽ и отвечает за день-два.

Хелпер делает первый проход за минуту и примерно за 8 ₽: находит опасные пункты, цитирует их
дословно и переводит на человеческий — чем конкретно это грозит подписанту.

## Как работает

Продукт живёт целиком внутри Telegram: бот — вход, мини-апп — экран.

```
Telegram ─→ мини-апп ─→ POST /api/extract ─→ pdfplumber ─→ текст договора
                              (доли секунды)                     │
                        документ уже на экране, по нему идёт луч │
                                                                 ▼
                        POST /api/analyze ─→ модель возвращает JSON:
                                             цитата + уровень + перевод
                                                     │
                                             привязка цитат к тексту (start/end)
                                                     │
                                    ┌────────────────┴────────────────┐
                        не нашлась дословно                     нашлась
                        переспрос только по ней        подсветка прямо в тексте
```

Один FastAPI-контейнер отдаёт и статику мини-аппа, и API; бот на polling живёт
фоновой задачей в его `lifespan`. Так и задумано: в Amvera каждое приложение
тарифицируется отдельно, поэтому веб и бот делят один контейнер.

**Почему извлечение и разбор — два запроса.** Если отдавать текст вместе с готовым
отчётом, анимация сканирования идёт по пустому экрану — то есть это обычный спиннер,
только дороже. Разделив шаги, документ показываем сразу, и луч действительно проходит
по тому тексту, который сейчас читает модель.

Неочевидное здесь одно, и на нём всё держится: **модель обязана цитировать договор дословно**.
Свободный текст с эмодзи-заголовками читается нормально, но из него нельзя подсветить пункт
внутри документа и нельзя измерить качество — две разные формулировки одного риска не сравнить
между собой. Поэтому ответ — структура (`schema.py`), а каждая цитата ищется в исходном тексте
и получает координаты. Не нашлась — модель переспрашивают точечно, только по потерянным
цитатам; так ретрай стоит 2 ₽ вместо 6 ₽ и не упирается в лимит токенов.

Поиск цитаты терпит расхождения в пробелах и регистре: модель почти всегда схлопывает переносы
строк из PDF, и точное сравнение теряло бы половину находок.

**Скан вместо PDF.** Бывает, что внутри файла нет ни одной буквы — только фотография бумаги.
Тогда `pdfplumber` возвращает пустоту, и мы рендерим страницы в картинки (`pypdfium2`) и
просим модель **переписать текст**, а не разбирать изображение. Разбор картинки выдал бы
находки, которые не к чему привязать: подсветка живёт на координатах цитат внутри текста.
Переписали — дальше идёт тот же конвейер, что и для обычного PDF, вместе с эвалами.

Распознавание стоит денег, поэтому на нём стоит потолок в 5 страниц (`OCR_MAX_PAGES`), оно
списывается из той же суточной корзины, что и разбор, и идёт на модели полегче: переписать
текст проще, чем его анализировать. Страницы распознаются параллельно — последовательно
это полминуты ожидания на ровном месте.

**Поделиться разбором.** Готовый отчёт сохраняется по короткой ссылке `/r/<токен>` — её
открывают без Telegram и без входа, а та же страница печатается в PDF по `/r/<токен>.pdf`.
Продукт, результатом которого нельзя поделиться, дальше одного человека не уходит.

Сохраняется при этом **только отчёт, а не договор**: цитаты опасных пунктов и их разбор.
Держать чужой договор целиком ради кнопки «поделиться» — плохая сделка, ценность маленькая,
а утечка дорогая. Ссылка живёт 30 дней, доступ даёт знание адреса — токен случайный и
достаточно длинный, чтобы его не подобрали перебором.

## Стек

Python 3.11 · aiogram · Pydantic · pdfplumber · pypdfium2 · structlog · Sentry ·
OpenRouter (Claude Sonnet 5 на разбор, Haiku 4.5 на распознавание сканов, с фолбэком) ·
Playwright · Docker · GitHub Actions

## Запуск

```bash
cp .env.example .env    # заполнить ключи
docker compose up --build
```

Без Docker:

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
python bot.py
```

## Разработка

```bash
ruff check --fix .        # линт
ruff format .             # форматирование
pytest -q                 # тесты
python evals/run_eval.py  # эвалы на LLM-часть
```

## Качество LLM-части

| Метрика | Значение |
|---|---|
| Размер датасета | 8 кейсов: 5 реальных договоров, инъекция, не-документ, пустая страница |
| Точность на датасете | не измерена после расширения датасета |
| Стоимость одного разбора | считается по факту, из ответа OpenRouter |

Метрика проверяет две вещи: нашлись ли размеченные ловушки и привязались ли все цитаты к
тексту. Цитата без привязки — это отчёт, который нечего подсветить, поэтому такой прогон
считается провалом целиком. Датасет и разметка — в [evals/](evals/).

Число в таблице появится после первого прогона на новом датасете. Писать сюда старое «100%
на двух кейсах» нельзя: это была метрика другого, вдвое меньшего датасета, и на собеседовании
такая цифра звучит хуже, чем честное «ещё не мерил».

## Безопасность

Мини-апп открыт по обычной https-ссылке, поэтому запрос к `/api/*` может отправить кто
угодно — а каждый разбор стоит живых денег. Единственное доказательство, что запрос
пришёл из Telegram, — подпись `initData`, которая считается на боттокене ([tgauth.py](tgauth.py)).
Сверяем её `hmac.compare_digest`, проверяем свежесть и только потом смотрим на `user`.
Плюс лимит разборов в сутки на пользователя и потолок размера файла.

Текст договора попадает в мини-апп только через `textContent`: внутри PDF может лежать
что угодно, включая разметку, и превращать её в DOM нельзя.

В Sentry не уходит ни содержимое договоров, ни тексты запросов к модели — `send_default_pii`
выключен намеренно. Трекер ошибок нужен, чтобы узнать о поломке, а не чтобы собирать копии
чужих документов.
